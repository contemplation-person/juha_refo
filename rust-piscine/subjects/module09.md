# Module 09 — 최종 과제 BSQ

> 지도에서 장애물을 피해 그릴 수 있는 가장 큰 정사각형을 찾는다. 42 피신의 마지막 관문인 BSQ(Biggest SQuare)를 러스트로 다시 푼다.

읽을거리: The Rust Book 12장 (입출력 프로젝트), `std::io`, `std::fs` 문서

공통 규칙은 [README](../README.md#규칙)를 따른다. 이 과제는 하나뿐이지만 케이스가 30개가 넘는다. 하나라도 틀리면 KO 다.

---

## ex00 : bsq

| 항목 | 내용 |
|------|------|
| 제출 위치 | `rendu/module09/ex00/` |
| 종류 | 실행 파일 — `cargo new --vcs none --name bsq ex00` |
| 패키지 이름 | `bsq` (이 과제만 디렉터리 이름과 다르다) |
| 제출 파일 | `Cargo.toml`, `src/` 아래 파일 전부 |
| 금지 | 없음 |

### 지도 형식

```
9.ox
...........................
....o......................
............o..............
...........................
....o......................
...............o...........
...........................
......o..............o.....
..o.......o................
```

첫 줄은 머리글(header)이다. 머리글은 두 부분으로 읽는다.

- 마지막 세 글자는 차례대로 빈칸, 장애물, 채움 기호다. 위 예시에서는 `.`, `o`, `x` 다.
- 그 앞은 전부 숫자이고 지도 줄 수를 뜻한다. 위 예시에서는 `9` 다.

둘째 줄부터가 지도다.

### 올바른 지도의 조건

아래 중 하나라도 어기면 잘못된 지도다.

| 조건 | 예시 (잘못된 경우) |
|------|------|
| 머리글은 4글자 이상이다 | `ox` |
| 줄 수 자리는 숫자로만 이루어진다 | `.ox`, `2a.ox` |
| 줄 수는 1 이상이다 | `0.ox` |
| 세 기호는 서로 다르다 | `2..x` |
| 세 기호는 출력 가능한 ASCII 문자다 (공백 포함, 코드 0x20~0x7E) | 탭 문자 |
| 실제 지도 줄 수가 머리글의 줄 수와 같다 | `5.ox` 인데 3줄 |
| 모든 줄의 길이가 같고 1 이상이다 | 4칸, 3칸, 4칸 |
| 지도에는 빈칸 기호와 장애물 기호만 있다 | 채움 기호 `x` 가 섞인 지도 |
| 머리글을 포함한 모든 줄은 줄바꿈(`\n`)으로 끝난다 | 마지막 줄에 `\n` 이 없다 |

빈칸이 하나도 없는 지도는 올바른 지도다. 채울 곳이 없으므로 지도를 그대로 출력한다.

### 할 일

빈칸으로만 이루어진 가장 큰 정사각형을 찾는다. 그 칸들을 채움 기호로 바꿔 지도 전체를 출력한다. 머리글은 출력하지 않는다.

```
$ cargo run -q -- example.map
.....xxxxxxx...............
....oxxxxxxx...............
.....xxxxxxxo..............
.....xxxxxxx...............
....oxxxxxxx...............
.....xxxxxxx...o...........
.....xxxxxxx...............
......o..............o.....
..o.......o................
$
```

가장 큰 정사각형이 여러 개일 수 있다. 그때는 정사각형의 왼쪽 위 칸을 기준으로 고른다.

1. 가장 위에 있는 것을 고른다.
2. 높이가 같으면 가장 왼쪽에 있는 것을 고른다.

```
입력 (4.ox)      출력
ooooo..          oooooxx
ooooo..          oooooxx
..ooooo          ..ooooo
..ooooo          ..ooooo
```

2 × 2 정사각형이 오른쪽 위와 왼쪽 아래에 하나씩 있다. 왼쪽 아래가 더 왼쪽이지만, 오른쪽 위가 더 위에 있으므로 오른쪽 위를 채운다.

### 입력과 출력

| 상황 | 동작 |
|------|------|
| 인자가 있다 | 인자로 받은 파일을 순서대로 하나씩 처리한다 |
| 인자가 없다 | 표준 입력(stdin)에서 지도 하나를 읽는다 |
| 지도가 잘못됐거나 파일을 열 수 없다 | 표준 에러(stderr)에 `map error` 와 줄바꿈을 출력한다. 그 파일은 건너뛰고 다음 파일로 간다 |
| 지도를 둘 이상 출력한다 | 출력한 지도와 지도 사이에 빈 줄 하나를 넣는다 |

잘못된 지도는 표준 출력에 아무것도 남기지 않는다. 따라서 빈 줄도 성공한 지도 사이에만 들어간다.

```
$ cargo run -q -- a.map bad.map c.map
xx
xx

oxo
map error          ← 이 줄은 stderr 로 나간다
$
```

종료 코드는 언제나 0 이다. 잘못된 지도가 있어도 0 으로 끝낸다.

정상 지도를 처리할 때 stderr 에는 아무것도 출력하지 않는다. 디버그용 출력을 남기면 KO 다.

### 속도

채점에는 1000 × 1000 지도가 나온다. 그 안의 가장 큰 정사각형은 한 변이 300 칸이 넘는다. 시간 제한은 디버그 빌드 기준 10초다.

모든 칸에서 정사각형을 키워 가며 매번 검사하면 시간 안에 끝나지 않는다. 힌트는 하나만 준다.

> 어떤 칸을 오른쪽 아래 꼭짓점으로 하는 가장 큰 정사각형의 크기는, 그 칸의 위·왼쪽·왼쪽 위 이웃 칸이 가진 같은 값만 알면 정해진다.

이 생각을 표로 쌓아 가는 방법을 동적 계획법(dynamic programming)이라고 부른다. 계산은 각 칸을 한 번씩만 본다.

### 힌트

- 파일은 `std::fs::read` 로 바이트 묶음(`Vec<u8>`)째 읽을 수 있다. 지도는 ASCII 이므로 `String` 보다 바이트로 다루는 편이 편하다.
- 표준 입력은 `std::io::stdin().read_to_end(&mut buf)` 로 끝까지 읽는다. `use std::io::Read;` 가 필요하다.
- `println!` 을 한 줄마다 부르면 느리다. 출력을 `String` 이나 `Vec<u8>` 에 모아 한 번에 쓰거나, `std::io::BufWriter` 로 감싼다.
- `BufWriter` 를 쓴다면 stderr 에 쓰기 전에 stdout 을 `flush` 한다. 그래야 터미널에서 출력 순서가 뒤섞이지 않는다.
- 검사 로직을 `fn parse(data: &[u8]) -> Option<Map>` 처럼 따로 떼면 "잘못된 지도면 바로 `None`" 이 `?` 한 글자로 끝난다.
- 직접 지도를 만들어 시험해 본다. 줄 수가 틀린 지도, 마지막 줄바꿈이 없는 지도, 빈 파일 같은 이상한 입력이 채점의 절반이다.
